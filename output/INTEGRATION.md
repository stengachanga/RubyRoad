# NovaPay Payout API — Space Payments integration guide

Generated by RubyRoad 0.3.0 from OpenAPI `1.0.0`.

Drop `novapay_service.rb` into `app/services/provider/novapay_service.rb` (already copied there by `./integrate`).

Overrides file: `examples/provider_api.overrides.yaml` (`amount_unit`, `required_if`, `signature_encoding`). Generic keys, not a provider SDK.

## Auth

| | |
| --- | --- |
| Type | ApiKeyAuth (header: X-API-Key) |
| Header | `X-API-Key` |
| Storage | Store the API key in `providers.credentials` (encrypted). Map it to `NOVAPAY_API_KEY` or pass `{ "api_key" => "..." }` into the service constructor. |
| Sandbox | `https://api.sandbox.novapay.example/v1` |
| Production | `https://api.novapay.example/v1` |

```ruby
Provider::NovapayService.new(
  credentials: { "api_key" => ENV["NOVAPAY_API_KEY"], "callback_secret" => ENV["NOVAPAY_CALLBACK_SECRET"] }
)
```

## Status mapping

When the spec has no mapping table, RubyRoad uses the assignment canon:
`pending` / `processing` → `in_progress`, `completed` → `approved`, `failed` / `cancelled` → `rejected`.
Extra keyword aliases (`succeeded`, `paid`, `declined`, …) are documented assumptions, not a Space Payments dump.

Provider status → Space Payments operation status.

| Provider | Space Payments |
| --- | --- |
| `pending` | `in_progress` |
| `processing` | `in_progress` |
| `completed` | `approved` |
| `failed` | `rejected` |
| `cancelled` | `rejected` |

## Error handling

| HTTP | Provider code (typical) | Action |
| --- | --- | --- |
| 400 | invalid request | reject |
| 401 | unauthorized / invalid API key | alert ops, block provider |
| 402 | insufficient_balance | retry later |
| 409 | idempotency replay / invalid_status | success if duplicate create; reject cancel |
| 422 | validation_error | reject |
| 429 | rate_limit_exceeded | backoff (`Retry-After`) then retry |
| 500 | internal_error | retry and alert ops |

`create_request` rescues `Provider::RateLimitError` and `Provider::UnauthorizedError` (and Faraday equivalents) into `failure(...)`.

```json
{
  "external_method": "novapay",
  "gateway": "Provider::NovapayService",
  "base_url": "https://api.sandbox.novapay.example/v1",
  "auth": {
    "type": "api_key",
    "header": "X-API-Key",
    "scheme": "ApiKeyAuth"
  },
  "webhook": {
    "path": "/webhooks/payout",
    "signature_header": "X-NovaPay-Signature",
    "algorithm": "HMAC-SHA256",
    "encoding": "hex"
  },
  "amount": {
    "scale": 100,
    "currency": "RUB"
  }
}
```

Space Payments `operation.amount` is **major units** (RUB). The OpenAPI amount field is **minor units**; the generated payload uses `(operation.amount * 100).to_i`.

## Webhook signature

```
X-NovaPay-Signature = hex( HMAC-SHA256(callback_secret, raw_body) )
```

The provider signs the **raw request body** with HMAC-SHA256 and sends the hex digest in `X-NovaPay-Signature`. `process_callback` rejects the event if the digest does not match.

Events: payout.completed, payout.failed, payout.processing, payout.cancelled. Completed → `approve_operation`; failed/cancelled → `reject_operation`.
